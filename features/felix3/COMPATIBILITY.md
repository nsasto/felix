## Upgrade guidance

Run `felix v3 migrate --harness <claude-code|opencode|codex|grok-build>` to inspect the V3 configuration preview. Add `--apply` only after reviewing it. Migration creates separate V3 configuration and installs the provider-neutral Felix skill; it does not rewrite V2 project data. To start a new V3 project, use `felix v3 setup --harness <provider>`.

Grok runs headlessly with the `dontAsk` permission mode, which silently denies tools without an explicit allow rule. Felix's sample grants native `Bash` during building and scoped Git commands during review. Diagnosis on Grok CLI 1.0.52 showed compound terminal calls can return cancellation even when their individual commands are allowed. A 2026-10-18 smoke completed planning, build, and independent validation, then reproduced the issue in review when Grok combined `git status --porcelain` with a second command. Felix now adds one-command-at-a-time guidance to every Grok phase and leaves acceptance validation to the coordinator. The Felix 3 contract suite covers the guidance. A saved-session review-only retry returned an approved review without failed tools. Combined provider cost was $0.15542148. The local Cloud service was unavailable, and the original coordinator run remains blocked; a fresh full coordinator run is still needed. See xAI's [permissions guide](https://docs.x.ai/build/features/permissions) and [headless CLI guide](https://docs.x.ai/build/cli/headless-scripting). Keep Grok experimental until that workflow passes.
