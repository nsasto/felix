## Baseline at plan kickoff

### Felix

- Claude Code, OpenCode, and Codex adapters launch their native CLI in non-interactive JSON/JSONL modes.
- Each adapter reads stdout line by line, writes the original output to a local run artifact, maps selected events into Felix event kinds, and invokes the Felix event sink.
- Felix already skips raw output-oriented event kinds when building durable Cloud events.
- At kickoff, `Add-Felix3CloudEvent` sent live activity synchronously through `PublishRunActivity`; this plan replaces that path with a CLI-owned asynchronous publisher.
- The packaged C# CLI launches the Felix 3 PowerShell coordinator as a child process. The implemented handoff uses a current-user named pipe from PowerShell to the C# parent.

### Felix Cloud

- `POST /api/runs/{id}/activity` accepts allowlisted activity and broadcasts it without inserting it into the durable run event table.
- `GET /api/projects/{id}/activity/events` provides authenticated project-scoped SSE.
- `ProjectActivityBroadcaster` uses bounded in-memory asyncio queues and drops the oldest event when a subscriber is slow. It is process-local and has no replay.
- At kickoff, the existing Orchestration agent click-through did not display Felix 3 assistant output. The implementation adds a transient panel to that same detail view, scoped to its active Cloud run; it does not add another destination.

Topology check completed from the current source: Render's `startCommand` launches one Uvicorn process and does not set Uvicorn workers. `render.yaml` now sets `numInstances: 1` for the first release because `ProjectActivityBroadcaster` and viewer presence are process-local. Render documents that `numInstances` configures manual scaling and that an existing autoscaled service retains its autoscaling settings unless the Blueprint includes a `scaling` block. Therefore the production dashboard still needs verification: confirm the service is manually scaled to one, or cap autoscaling at one before enabling live output. Publisher and browser requests routed to different instances will otherwise miss each other. Do not assume a source change proves the deployed instance count.
